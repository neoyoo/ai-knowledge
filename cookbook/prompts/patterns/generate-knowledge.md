# Generate Knowledge

> 先让模型生成相关知识/事实，再用这些知识回答问题——相当于"自己给自己开卷"，激活模型深层知识而无需外部检索。

## 本质

想象你在考试前先默写一遍相关知识点，再用这些知识点回答题目。Generate Knowledge 对 LLM 做的正是同一件事：第一步让模型把它知道的相关事实、背景知识写出来；第二步基于这些显式知识做推理和回答。

这和 RAG 的直觉类似，但不需要外部数据库——模型在第一步相当于从自己的参数里"检索"知识并外显化，再在第二步用这些知识推理。两步 prompt chain，零基础设施。

核心价值在于：直接问问题时，模型倾向于在单次 forward pass 里快速"猜"答案，深层知识可能激活不充分；先生成知识再回答，把相关背景显式写入上下文，推理过程有了可以"踩"的脚手架。来自 Liu et al. (2022) 的研究表明，这个方法在常识推理任务上显著提升准确率。

## 什么时候用

**没有外部知识库可检索** — 没有 RAG 基础设施、也没有时间建向量库，但模型本身知道相关领域知识。

**激活模型深层知识** — 模型对某个领域有丰富训练，但直接问答时知识激活不充分，生成的知识步骤相当于热身。

**常识推理任务** — 涉及世界知识、领域知识的判断题、True/False 题，错误往往来自直觉猜测而非知识缺失。

**需要多角度知识的问题** — 生成多条独立知识，再整合为答案，天然支持多角度分析。

## 什么时候不用

**有外部知识源时用 RAG** — 外部真实数据比模型"自生"知识更可靠，有基础设施就优先 RAG。

**需要最新信息** — 模型知识有训练截止日期，时效性信息（股价、新闻、最新政策）不要用此方法，生成的"知识"可能已过期。

**事实准确性极高要求** — 第一步生成的知识本身可能包含幻觉，会被带入第二步的推理；高风险场景（医疗诊断、法律判断）不适合依赖模型自生知识。

**简单直接的查询** — "巴黎是法国首都吗"这类问题直接回答即可，生成知识步骤是额外开销。

## 模板

### 基础版：两步顺序调用

**Step 1 — 知识生成**

```text
请生成关于以下问题的相关背景知识和事实。只输出知识，不要回答问题本身。

问题：{{question}}

知识：
```

**Step 2 — 基于知识回答**

```text
问题：{{question}}

相关知识：{{knowledge_from_step1}}

基于以上知识，请解释并回答这个问题：
```

---

**完整示例（高尔夫规则）：**

Step 1 提示词：

```text
请生成关于以下问题的相关背景知识和事实。只输出知识，不要回答问题本身。

问题：高尔夫比赛的目标是尽量获得比别人更高的分数吗？

知识：
```

Step 1 输出（示例）：

```text
高尔夫是一种精准的球杆运动，目标是用尽可能少的击球次数（杆数）将球打入球洞。
标准高尔夫球场共 18 洞，每洞有一个"标准杆"（par）作为参考。
比赛以总杆数计分，杆数越少越好；低于标准杆的成绩称为"birdie"或"eagle"，
高于标准杆称为"bogey"。最终比赛中总杆数最少的选手获胜，不是分数最高的获胜。
```

Step 2 提示词：

```text
问题：高尔夫比赛的目标是尽量获得比别人更高的分数吗？

相关知识：高尔夫是一种精准的球杆运动，目标是用尽可能少的击球次数（杆数）将球打入球洞。
标准高尔夫球场共 18 洞，每洞有一个"标准杆"（par）作为参考。
比赛以总杆数计分，杆数越少越好；低于标准杆的成绩称为"birdie"或"eagle"，
高于标准杆称为"bogey"。最终比赛中总杆数最少的选手获胜，不是分数最高的获胜。

基于以上知识，请解释并回答这个问题：
```

Step 2 输出（示例）：

```text
不是。高尔夫的目标是用尽可能少的击球次数完成全部球洞，而不是获得更高的分数。
比赛以总杆数计分，杆数越少越优秀。"分数更高获胜"是对高尔夫规则的常见误解，
实际上低杆数才是获胜关键。
```

**Few-shot 知识生成（更稳定的知识质量）**

用几个示例对子告诉模型你期望的知识格式和深度：

```text
Input: 希腊比墨西哥大。
Knowledge: 希腊国土面积约 131,957 平方公里，墨西哥约 1,964,375 平方公里，墨西哥约为希腊的 14.9 倍。

Input: 眼镜总是会起雾。
Knowledge: 眼镜起雾是因为温暖潮湿的空气（如呼出的气体）接触到相对较冷的镜片，
水蒸气冷凝成细小水珠形成薄膜。这一现象在温差较大时更为明显，并非始终发生。

Input: {{new_question}}
Knowledge:
```

### Agent 集成版：知识生成作为 pipeline 前置步骤

在需要领域知识的 agent 任务中，将知识生成嵌入为 reasoning 阶段：

```text
你是一个专业分析 agent。处理用户问题时，按以下两步进行：

第一步：在 <knowledge> 标签内，列出与该问题相关的背景知识、已知事实和领域原则。
不需要回答问题，只写知识。

第二步：在 <answer> 标签内，基于 <knowledge> 中的内容，给出分析和回答。
回答必须引用 <knowledge> 中的具体知识点，不得引入 <knowledge> 外的未验证信息。

---

用户问题：{{user_question}}
```

输出格式示例：

```text
<knowledge>
- 知识点 1：...
- 知识点 2：...
- 知识点 3：...
</knowledge>

<answer>
基于以上知识，...
</answer>
```

这种结构的优势：`<knowledge>` 块可被提取用于调试、日志、验证，也可以被人工审核后再进入下一步推理。

### 多知识版本 + 置信度选择

生成多条独立知识，再根据一致性选择最可靠的答案（类似 Generate Knowledge 论文中的做法）：

**Step 1** — 生成 N 条独立知识：

```text
请从 {{n}} 个不同角度，分别生成关于以下问题的背景知识。
每条知识独立编号，不要相互引用。

问题：{{question}}
```

**Step 2** — 基于每条知识独立推理，再整合：

```text
以下是关于"{{question}}"的几条背景知识：

知识 1：{{knowledge_1}}
知识 2：{{knowledge_2}}
知识 3：{{knowledge_3}}

请分别基于每条知识给出答案，然后综合所有答案给出最终结论，
并说明哪条知识支撑最强、你的置信度如何。
```

## Generate Knowledge vs RAG

| 维度 | Generate Knowledge | RAG |
|------|-------------------|-----|
| 知识来源 | 模型参数内部知识 | 外部真实文档/数据库 |
| 基础设施 | 零依赖，纯 prompt | 需要向量库、检索器 |
| 知识时效 | 受训练截止日期限制 | 可接入实时数据 |
| 事实可靠性 | 可能含幻觉 | 可溯源、可验证 |
| 延迟 | 两次 LLM 调用 | 一次检索 + 一次 LLM |
| 适用场景 | 常识推理、无知识库时的快速方案 | 有事实文档、需要引用来源 |
| 知识覆盖 | 受限于模型训练数据 | 可定制私有领域知识 |

核心区别：RAG 是"去图书馆查书"，Generate Knowledge 是"先把自己记得的写下来"。前者更可靠但有成本，后者零成本但自带幻觉风险。

## 组合与选择

**Generate Knowledge + CoT** — 先生成知识，再基于知识做链式推理。两步都是推理增强，叠加效果明显。适用于需要领域知识 + 多步逻辑的复杂问题。实现：Step 1 生成知识，Step 2 的 prompt 加上 "Let's think step by step"。

**Generate Knowledge + Prompt Chaining** — 知识生成作为 pipeline 第一步，后续步骤用不同角度处理生成的知识。适用于长文档分析、多角度研究报告等场景。

**Generate Knowledge + Self-Consistency** — 多次生成不同知识（temperature > 0），每条知识独立推理出答案，取多数答案。比单次 Generate Knowledge 更鲁棒，代价是调用次数倍增。适用于高精度常识推理任务。

**Generate Knowledge vs RAG** — 有外部知识库用 RAG；没有基础设施、问题涉及通用常识、快速原型阶段用 Generate Knowledge。两者也可以叠加：先用 RAG 检索外部知识，再让模型补充自身相关知识，混合喂给第二步推理。

## 模型差异

| 模型 | 表现描述 | 注意事项 |
|------|---------|---------|
| Claude 4 | 知识生成质量高，覆盖面广，不确定时会主动标注；`<knowledge>` 标签格式配合良好 | Extended thinking 模式下可省略知识生成步骤，模型内部已做类似处理；标准模式下显式两步效果更稳定 |
| GPT-4 | 知识生成详实，few-shot 示例对风格影响大；o1/o3 系列内部推理已包含知识激活，显式 Generate Knowledge 收益递减 | o1/o3 不需要显式 Step 1；GPT-4 标准版显式两步有明显收益 |
| Gemini 2 | 知识生成格式整洁；Flash 系列对中文领域知识覆盖偶有缺口 | 知识生成时建议限定长度上限，否则有时输出过于冗长 |
| 开源模型（LLaMA 3、Qwen 2.5） | 70B+ 参数模型效果接近闭源；小模型（7B 以下）生成的知识质量不稳定，可能直接包含错误事实 | 小模型建议加 few-shot 示例约束知识格式；知识质量需人工抽检 |

## 常见踩坑

**生成的知识本身含幻觉** — 现象：Step 1 输出了错误或混淆的事实，Step 2 基于错误知识得出错误结论，但推理逻辑看起来完全自洽。原因：Generate Knowledge 的根本局限——模型不能凭空变出正确知识，只是让已有知识显式化。避免方式：高风险场景用 RAG 替代；或在 Step 2 加指令"如果提供的知识中有你不确定的内容，请明确标注，不要直接使用"；或在 Step 1 结束后加一轮知识验证步骤。

**知识生成跑偏——直接给出答案** — 现象：Step 1 prompt 要求生成知识，但模型直接回答了问题。原因：模型理解为 QA 任务，跳过知识生成直接推理。避免方式：Step 1 prompt 明确强调"只输出背景知识和事实，不要回答问题本身，不要做判断"；也可以用 few-shot 示例展示正确的知识格式。

**知识量过多导致第二步噪声过大** — 现象：Step 1 生成了大量宽泛知识，Step 2 模型注意力被分散，回答不聚焦。原因：知识生成没有约束范围和数量。避免方式：Step 1 加数量限制（"生成 3-5 条最相关的知识点"）；或加范围限制（"只生成与判断 X 是否正确直接相关的知识"）。

**训练截止日期陷阱** — 现象：生成的知识是过时的，导致回答错误（如过时的法规、已更新的技术规范）。原因：模型知识冻结在训练截止时间。避免方式：时效性强的问题加上免责声明，或改用 RAG 接入实时数据源；在 Step 1 prompt 加"如果这是时效性信息，请明确说明你的知识可能已过期"。

**两步增加延迟影响用户体验** — 现象：两次 LLM 调用导致总响应时间翻倍。原因：Generate Knowledge 本质是串行两步。避免方式：评估任务是否真的需要两步，简单问题退化为单步；或将 Step 1 知识缓存（相同类型问题复用知识）；或将两步合并为单次调用（在同一 prompt 里用 XML 标签分隔，牺牲一点可控性换延迟）。
