# Vague Instructions

> 指令模糊不清，模型只能猜测你的意图，每次输出都不一样。

## 症状

- 同一个 prompt 跑两次，结果风格、长度、格式完全不同
- 你看到输出后需要说"不对，我的意思是……"才能澄清
- prompt 里充斥着"帮我处理一下"、"优化一下"、"写好一点"之类的词
- 对输出的期望只存在于你脑子里，从未写进 prompt

## 错误示例

```text
帮我优化这段文案，让它更好。

原文：我们的产品很棒，功能很多，价格也不贵，欢迎购买。
```

"更好"是什么意思？更简洁？更有感染力？更专业？更符合某个平台的风格？模型只能随机选择一个方向，你得到的是模型对"更好"的定义，不是你的定义。

另一个常见变体：

```text
把这份报告总结一下。
```

多长？给谁看（技术人员 vs 管理层）？要保留哪些内容？输出格式是段落还是要点？全都没说。

## 为什么有害

模型没有读心术。它唯一的信息来源是你给的 context。"优化"、"更好"、"总结"这类词在不同语境下的含义差距巨大：

- "优化文案"可以是：删减冗词 / 调整语气 / 换用更有力的动词 / 重新排列卖点顺序
- "总结报告"可以是：一句话摘要 / 三段结构化概述 / 按主题分块的要点列表 / 高管版 executive summary

当指令模糊时，模型会激活其训练分布里最常见的"默认"行为。这个默认行为可能和你的期望完全不搭。更危险的是：模型输出听起来总是"合理的"，你很难发现它根本没有满足你真正的需求。

在自动化 pipeline 里，模糊指令的危害被放大 10 倍——没有人工确认环节，错误的输出会直接流入下游。

## 正确做法

把你脑子里隐含的期望全部外显化。指令要回答四个问题：**做什么 / 给谁看 / 什么格式 / 什么限制**。

```text
请将以下产品文案改写为适合小红书发布的风格：
- 目标受众：25-35 岁女性，关注生活品质
- 长度：100-150 字
- 语气：亲切、真实，避免硬广感
- 保留：价格优势这个卖点
- 禁止：夸大宣传词汇（"最"、"第一"、"绝对"）

原文：我们的产品很棒，功能很多，价格也不贵，欢迎购买。
```

总结示例的修正版：

```text
请将以下技术报告总结为适合 C-level 管理者阅读的执行摘要：
- 长度：不超过 200 字
- 格式：3 个要点，每点一句话
- 重点：业务影响和决策建议，略去技术细节
- 输出语言：中文

[报告正文]
```

## 修复检查清单

- [ ] 我的 prompt 里是否有"处理一下"、"优化"、"改进"、"更好"之类的模糊动词？如果有，替换为具体行动
- [ ] 目标受众是否明确（给谁看、专业背景如何）？
- [ ] 期望输出的长度或规模是否有约束（字数/条数/段落数）？
- [ ] 输出格式是否指定（段落/列表/JSON/表格/代码）？
- [ ] 有没有"不要做什么"的负向约束（禁止使用某种风格、不要包含某些内容）？
- [ ] 如果把这个 prompt 给一个不认识你的人，他能猜到你期望什么输出吗？
