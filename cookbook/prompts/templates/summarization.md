# Summarization Template

> 把长文档或多轮对话压缩成指定长度和格式的摘要，从一句话 TL;DR 到分层结构摘要，适配不同消费场景。

## 场景描述

摘要是最高频的 LLM 任务之一，但"摘要"本身是个宽泛的词。根据下游用途的不同，你需要的摘要形态差异很大：

- 给领导看的 → 一句话结论 + 三条关键点
- 给下游 agent 用的 → 保留结构化字段（决策、行动项、日期）
- 长文档压入有限 context → Map-Reduce 分段聚合
- 多轮对话归档 → 保留关键决策，丢掉闲聊

摘要任务的核心挑战不是"压缩"，而是**选择性保留**——什么信息对目标场景重要，什么可以丢弃。这个判断需要在 prompt 里明确指定，否则模型会按通用重要性打分，可能保留你不需要的内容，丢掉你最需要的细节。

## 模板

### 1. 基础摘要（固定长度）

适用于：快速阅读、内容审核、消息通知

```text
请将以下内容摘要为不超过 {{max_words}} 字的段落。

要求：
- 保留核心论点和关键结论
- 去掉举例、铺垫和重复表述
- 使用原文的术语，不要引入新词

内容：
{{content}}

摘要：
```

---

### 2. 分层摘要（TL;DR + 要点 + 详细）

适用于：技术文档、会议纪要、报告归档

```text
请对以下内容生成三层摘要：

**第一层（一句话）**：用一句话概括核心结论，不超过 30 字。
**第二层（要点列表）**：列出 3-5 条关键信息，每条不超过 20 字，用 bullet 格式。
**第三层（详细摘要）**：完整摘要，不超过 {{detail_word_limit}} 字，保留重要细节、数据和背景。

内容：
{{content}}

输出格式：
## 一句话
[第一层]

## 关键要点
- [要点 1]
- [要点 2]
...

## 详细摘要
[第三层]
```

---

### 3. 对话摘要（保留决策和行动项）

适用于：多轮对话归档、agent session 压缩、会议记录

```text
请分析以下对话记录，提取关键信息并生成结构化摘要。

提取规则：
- **决策**：已明确做出的选择或结论（包括被否决的方案）
- **行动项**：需要执行的任务，注明负责人（如有）和截止时间（如有）
- **未解决问题**：讨论了但没有得出结论的问题
- **背景信息**：理解后续对话必须保留的关键上下文

忽略：问候语、重复确认、离题闲聊

对话记录：
{{conversation}}

输出格式：
## 决策
- [决策内容]

## 行动项
- [ ] [任务描述]（负责人：{{owner}}，截止：{{deadline}}）

## 未解决问题
- [问题描述]

## 背景上下文
[一段话，供下次对话恢复上下文用]
```

### 4. Map-Reduce 长文档摘要

适用于：超出单次 context 限制的长文档（论文、法律文件、代码库文档）

**Step 1 — Map（分段摘要）**，对每个分块分别调用：

```text
这是一份长文档的第 {{chunk_index}}/{{total_chunks}} 段。

请仅基于本段内容生成局部摘要，不要推测其他段落内容。

要求：
- 保留本段的核心论点、数据和结论
- 标注本段讨论的主题关键词（用于后续合并）
- 不超过 {{chunk_summary_words}} 字

文档第 {{chunk_index}} 段：
{{chunk_content}}

局部摘要：
```

**Step 2 — Reduce（合并摘要）**，将所有局部摘要合并：

```text
以下是一份长文档各段的局部摘要，共 {{total_chunks}} 段。

请综合所有局部摘要，生成一份全文摘要。

要求：
- 识别跨段落的主线论点
- 去除各段之间重复的内容
- 保留重要数据、结论和关键名词
- 最终摘要不超过 {{final_summary_words}} 字

各段局部摘要：
{{chunk_summaries}}

全文摘要：
```

---

### 5. 输出格式切换

同一段内容，按下游需求切换输出格式：

```text
请将以下内容摘要为{{output_format}}格式。

{{#if output_format == "纯文本"}}
输出一段连贯的文字，不使用标题和列表。
{{/if}}
{{#if output_format == "结构化JSON"}}
输出 JSON，字段：{ "title": string, "summary": string, "key_points": string[], "keywords": string[] }
{{/if}}
{{#if output_format == "bullet points"}}
用 bullet 列表输出，每条独立完整，不超过 20 字。
{{/if}}

内容：
{{content}}
```

实际使用时选定一种格式，不需要保留条件分支——这里的写法是为了展示三种格式的 prompt 差异。

## 自定义指南

**`{{max_words}}`** — 目标摘要字数上限。经验值：邮件通知 50-100 字；技术报告 200-400 字；归档摘要 500-800 字。设太小会丢失关键信息，设太大会导致模型偷懒不压缩。

**`{{detail_word_limit}}`** — 分层摘要第三层的字数。建议原文字数的 10-20%。

**`{{chunk_summary_words}}`** — Map 阶段每段局部摘要的字数上限。建议原始分块字数的 15-25%，确保 Reduce 阶段的合并输入在 context 窗口内。

**`{{final_summary_words}}`** — Reduce 阶段全文摘要字数。视文档长度设置，通常 300-600 字足以覆盖大多数场景。

**`{{output_format}}`** — 下游消费格式。给人看选纯文本或 bullet；给程序消费选 JSON；给 agent 传递上下文选结构化（方便后续提取字段）。

**分块策略**（Map-Reduce）：
- 按段落分块：适合有明确段落结构的文档
- 按固定 token 分块（如 2000 tokens/块）：适合无结构的长文
- 重叠分块（每块前 10% 来自上一块末尾）：适合内容连续性强的叙事性文档，防止跨块信息丢失

## 使用示例

**场景：压缩 agent 对话历史**

```text
请分析以下对话记录，提取关键信息并生成结构化摘要。

提取规则：
- 决策：已明确做出的选择或结论（包括被否决的方案）
- 行动项：需要执行的任务，注明负责人（如有）和截止时间（如有）
- 未解决问题：讨论了但没有得出结论的问题
- 背景信息：理解后续对话必须保留的关键上下文

忽略：问候语、重复确认、离题闲聊

对话记录：
[User]: 我们要不要在 v2 里加分布式 session 支持？
[Assistant]: 分布式 session 的核心挑战是一致性和延迟，目前 DeerFlow 用 checkpointer 解决...
（30 轮对话省略）
[User]: 好，那先做单机版，v3 再考虑分布式。
[Assistant]: 确认，v2 只做单机 session，v3 评估分布式。

输出格式：
## 决策
- v2 实现单机 session，不做分布式
- v3 再评估分布式方案（参考 DeerFlow checkpointer 设计）

## 行动项
- [ ] 实现单机 session 持久化（负责人：Neo，截止：v2 里程碑）

## 未解决问题
- v3 分布式选型：Redis 还是数据库 checkpointer

## 背景上下文
正在开发 neoagent SDK v2，session 管理是核心模块。已调研 DeerFlow 的 checkpointer 方案，结论是单机优先，分布式留 v3。
```

**场景：技术报告分层摘要**

```text
请对以下内容生成三层摘要：
...
内容：
LLM 推理优化综述（8000 字论文）...

## 一句话
量化和投机解码是当前 LLM 推理加速最成熟的两条路线，各有适用边界。

## 关键要点
- INT4 量化在 7B 以下模型上精度损失可接受（< 1% MMLU 下降），70B+ 模型需 INT8 或混合精度
- 投机解码对长输出任务加速 2-3x，对短输出任务收益不明显
- KV Cache 压缩是长上下文场景的核心瓶颈，现有方案在 32K+ 上仍有较大精度损失
- Flash Attention 3 已在 H100 上实现接近理论带宽上限，是目前 attention 实现的最优选

## 详细摘要
...
```

## 适配建议

**给 agent 内部 context 压缩用** — 用对话摘要模板（模板 3），把输出中的"背景上下文"字段塞回下一轮的 system prompt。不需要保留完整对话历史，只保留决策和未解决问题。注意：压缩时机很重要，建议在 context 使用率超过 70% 时触发，而不是等到溢出。

**给人类阅读用** — 优先分层摘要（模板 2）。一句话满足 "3 秒扫描" 需求，要点列表满足 "30 秒阅读" 需求，详细摘要满足深度阅读。不要强迫读者一次性看完，让他们按需下钻。

**超长文档（> 50K tokens）** — 必须用 Map-Reduce（模板 4）。不要尝试把全文塞入单次请求——即使 context 窗口够大，注意力稀释会导致摘要质量下降，中间段落的信息容易被忽略。

**结构化下游消费（如数据库存储、API 返回）** — 用 JSON 格式变体，并在 prompt 末尾加一行：`只输出 JSON，不要添加任何解释性文字。` 搭配 [[structured-output]] 模式的 schema 约束更可靠。

**多语言内容** — 默认模型会用输入语言输出摘要。如需固定输出语言，在 prompt 开头明确：`请用中文输出摘要，即使原文是英文。`
